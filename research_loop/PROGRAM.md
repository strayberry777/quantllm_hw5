# 研究守则（给负责提出因子的 AI）

你的工作是**提出因子**，不是给因子打分。打分由固定的评价器（`bt/factor_eval.py`）和本目录的脚本完成，你不能修改它们。

## 每一轮

1. 读 `ledger.jsonl`（研究日志）和 `leaderboard.md`，了解已经试过什么、为什么失败
2. 提出 3–5 个新因子，每个写成 `factors/<名字>.py`：
   - 一个 `factor(d)` 函数，返回「交易日 × 股票」数组，值越大 = 预期越好
   - 一个 `HYPOTHESIS` 字符串：一句经济逻辑（为什么它应该有效），以及它想改进日志里的哪个问题
3. 运行 `python run_round.py <轮次> factors/a.py factors/b.py ...`：自动做前视检查，在训练期和验证期各评价一次，写入日志
4. 运行 `python leaderboard.py`，读结果，写下反思（`python run_round.py` 会提示在 `notes/` 里写一段）
5. 下一轮从反思出发：改进有希望的方向，放弃反复失败的方向

## 规则（不能违反）

- **看不到留出期**（2025-01 至 2026-09）。不得读取、计算或推断留出期的任何结果
- 不得修改 `bt/`、`config.json`、目标函数和晋级门槛
- 不得删除或改写日志；失败的因子同样要留在日志里
- 因子必须通过前视检查（第 t 行只能用第 t 日收盘及以前的数据）
- 与已有候选秩相关 > 0.8 的因子视为重复，不计入新发现
- 迭代结束后，由人决定是否对每个目标的冠军运行一次 `final_exam.py`；每个因子只能考一次

## 优化目标

同一份日志可以按不同目标排序（见 `config.json`）：IC、夏普、最大回撤、夏普与回撤各占一半的混合目标。
目标不同，选出的因子可能完全不同——这正是要研究的问题。
